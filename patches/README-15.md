# Патч 15 — первый запуск совдело.рф на сервере СовПути

Цель: Ubuntu 24.04, PHP 8.3 FPM, PostgreSQL 16, Nginx. Домен xn--b1aedylep.xn--p1ai (совдело.рф). Сборка Vue выполняется локально, Node на сервере не устанавливается. Источник релиза — зафиксированный Git-коммит, зависимости PHP устанавливаются по composer.lock отдельным системным пользователем.

## 1. Локально на Ubuntu

```bash
cd ~/Projects/sovdelo &&
unzip -o ~/Загрузки/sovdelo-patch-15-server-foundation.zip -d . &&
python3 deploy/tests/test_release.py &&
bash scripts/check-git.sh &&
git add deploy patches &&
git commit -m "СовДело: установка на сервер и HTTPS" &&
git push &&
bash deploy/package.sh ~/Загрузки/sovdelo-release.tar.gz &&
scp ~/Загрузки/sovdelo-release.tar.gz root@xn--b1aedylep.xn--p1ai:/root/sovdelo-release.tar.gz
```

Упаковка требует чистого Git (включая отсутствие неотслеживаемых файлов), извлекает HEAD во временный каталог, выполняет npm ci, 14 frontend-тестов и сборку. Артефакт содержит исходники и public/build; локальная база, .env, vendor, node_modules, runtime storage и кэш не включаются. Если Git сообщает о незакоммиченных предыдущих патчах, сначала сохранить именно их; не добавлять секреты, выгрузки БД или локальные вложения. Git push сохраняет исходники. Это первый ручной релиз из Git, не автоматическая отправка каждого push на сервер.

## 2. На сервере, от root

```bash
mkdir -p /root/sovdelo-installer &&
tar -xzf /root/sovdelo-release.tar.gz -C /root/sovdelo-installer ./deploy/server &&
bash /root/sovdelo-installer/deploy/server/install.sh /root/sovdelo-release.tar.gz
```

После успешного завершения:

```bash
bash /root/sovdelo-installer/deploy/server/finish-https.sh
```

Сначала домен отвечает 503, доступен только путь ACME для сертификата. finish-https выпускает сертификат для основного домена, включает HTTPS и перенаправление HTTP. www не добавляется: его DNS не подтверждён. Certbot при необходимости устанавливается из apt, его условия принимаются параметром --agree-tos. При наличии текущей ACME-учётной записи используется штатное поведение Certbot; новая регистрируется без email. Добавляется deploy-hook перечитывания Nginx при обновлении сертификата.

## Изоляция

- /var/www/sovdelo/releases/<дата-коммит>, current — активный релиз.
- /var/www/sovdelo/shared/.env — root:sovdelo 0640, новый постоянный APP_KEY и случайный пароль БД. Повторный запуск файл не заменяет.
- shared/storage — отдельные приватные файлы, логи, кэш представлений.
- PostgreSQL: роль и БД sovdelo; другой владелец существующей БД вызывает отказ. Нет сброса/очистки БД и глобальных изменений PostgreSQL.
- Пользователь sovdelo, FPM-пул sovdelo с отдельным сокетом; ondemand, до 3 процессов по 256 МБ.
- Nginx-конфигурация /etc/nginx/sites-available/sovdelo; отдельные логи, root current/public, приватные вложения через авторизованный PHP-контроллер.
- Отдельные sovdelo-queue и sovdelo-scheduler, запуск от sovdelo. Не добавлять одновременно cron schedule:run: schedule:work уже исполняет расписание.
- Выполняется graceful reload общих Nginx/PHP-FPM после проверки синтаксиса; конфиги СовПути не редактируются. PostgreSQL/OSRM не перезапускаются.

Установщик проверяет архив (пути, типы файлов, отсутствие .env/зависимостей/ссылок), наличие сборки и Git-метаданных. Composer запускается не от root. Код релиза после установки root-owned, PHP пишет только в свои runtime-каталоги. Если целевой каталог/конфиги заняты неизвестной установкой, выполнение останавливается. Повтор той же версии допустим; установка другого коммита поверх существующего сайта блокируется до настройки резервного копирования и процесса обновления с откатом. Автоматический CI/CD добавим следующим этапом после подтверждения первого запуска.

## Данные и проверки

Создаётся новая производственная база: зарегистрировать собственный аккаунт на сайте. Локальные аккаунты и пароли не копируются. После успешного запуска перенесём проекты/задачи JSON-импортом; файлы не входят в JSON и переносятся отдельно. Реальная почта, внешние бэкапы и проверка восстановления ещё не настроены — задачи SD-035/SD-005 остаются открытыми, этап сервера не считать полностью завершённым.

```bash
curl -I https://xn--b1aedylep.xn--p1ai
systemctl --no-pager --full status sovdelo-queue sovdelo-scheduler
```

finish-https также проверяет /up по локальному HTTPS с правильным именем сертификата. Затем вручную проверить главную СовПути, регистрацию СовДела, задачу, вложение, таймер и напоминание. PHP upload_max_filesize=12M, post_max_size=14M и Nginx 14m оставляют запас для приложения с ограничением файла 10 МБ. Сессии СовДела имеют отдельную cookie и привязку к своему домену.

При ошибке пришлите вывод команды. Не присылайте .env и пароли. Для диагностики используются storage/logs/laravel.log и journalctl -u sovdelo-queue -u sovdelo-scheduler. Ошибка миграций оставляет СовДело в maintenance для проверки, без автоматического отката схемы. Готовых production-данных этот первый установщик не удаляет. Процедуру обновлений, внешнюю копию и восстановление подготовим после первого запуска.
