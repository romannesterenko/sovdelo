## Как пользоваться

Кнопка «Импорт / экспорт» находится рядом с повторяющимися задачами над списком. Сначала сохранить изменения открытой задачи.

Экспорт включает все свои проекты и задачи, в том числе архив/корзину, чек-листы, метки, комментарии и историю времени с корректировками. Связи проектов и задач сохраняются. Активная сессия времени выгружается завершённым снимком на момент экспорта, текущий таймер не останавливается. При импорте время всегда становится завершённой историей, активные таймеры не создаются и существующий таймер не затрагивается. Причина закрытия импортированного времени — «import»; исходная причина остаётся в исходном JSON.

Содержимое вложений, шаблоны повторов, напоминания/центр уведомлений и настройки аккаунта в перенос не входят. Файл не является полной резервной копией. Никаких паролей, remember-token, session ID, путей хранения вложений или внутренних user_id в экспорте нет. Адаптер старого браузерного прототипа следует делать отдельно по реальному файлу его формата, если потребуется.

Импорт: выбрать JSON → стратегию дублей → «Проверить файл» → проверить количества/примеры → «Подтвердить импорт». Предпросмотр не пишет в БД. После смены файла или стратегии нужно проверить файл заново.

Лимиты: JSON до 5 МБ, до 200 проектов, до 1000 задач, суммарно до 20 000 записей с чек-листами, метками, комментариями, сессиями и корректировками. Экспорт тоже проверяется на возможность последующего импорта; при превышении лимитов выдаёт ошибку вместо неполного файла. Время сессии/корректировки — до 315 576 000 секунд. Все данные проходят серверную валидацию, проверку ссылок и уникальности идентификаторов; неподдерживаемые поля/версии отклоняются.

## Стратегии дублей

Каждый проект и задача получают постоянный UUID переноса. Совпадение определяется по UUID внутри текущего аккаунта, а не по названию. Архив и корзина тоже учитываются.

- «Пропустить существующие»: существующий проект используется повторно, существующая задача целиком пропускается вместе с её комментариями/временем. Изменения из более позднего экспорта не перезаписывают уже имеющиеся задачи. Если совпавший проект находится в архиве, новые задачи в нём тоже будут скрыты архивом проекта.
- «Создать отдельные копии»: создаются новые проекты и задачи с новыми UUID. Даже при совпадении названия это отдельные записи. Сознательный новый импорт с этой стратегией создаёт ещё один комплект копий.

Метки с одинаковым именем в аккаунте переиспользуются; их существующий цвет не меняется. Чек-листы сохраняют состояние отметок. Даты комментариев и корректировок времени сохраняются. Все импортируемые записи принадлежат текущему аккаунту; UUID другого аккаунта не даёт доступа к его данным.

Импорт выполняется одной транзакцией под общей блокировкой пользователя. Сбой откатывает весь импорт. Повтор того же запроса с тем же UUID операции возвращает первоначальный результат, включая стратегию копирования: можно повторить подтверждение после сетевой ошибки. Файл/стратегия для уже использованного ключа менять нельзя. Финальные количества рассчитываются заново внутри импорта, если после предпросмотра данные изменились.

## Проверки

10 новых backend-тестов, всего 82 WorkspaceTest: изоляция экспорта и архив/корзина; перенос чек-листа/меток/комментариев/времени; пропуск по UUID и отдельные копии; предпросмотр без записи и версия схемы; неверные ссылки/поля владельца; повтор запроса и изменённый файл; полный откат при ошибке записи; снимок активного времени без запуска; гости/битый/слишком большой файл; UUID разного регистра и неверная хронология времени.

Здесь PHP/Docker недоступны: backend-тесты запускаются командой установки на Ubuntu. TypeScript/Vite и существующие 8 frontend-тестов проверены при подготовке.

Ручная проверка: скачать JSON, импортировать в тот же аккаунт с «Пропустить существующие». Предпросмотр должен показать существующие задачи, подтверждение — 0 созданных задач. Обновить страницу: дублей нет. Для проверки переноса в другой аккаунт использовать отдельный тестовый аккаунт и сравнить проекты, чек-листы и историю времени.

## Откат

Откат миграции удаляет UUID переноса и журнал операций импорта, но не импортированные проекты, задачи, комментарии и время. Повторное назначение UUID после отката нарушит распознавание прежних файлов. Код и миграции откатывать согласованно, не использовать rollback вслепую после следующих миграций.
