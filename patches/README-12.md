## Что изменилось

Кнопка с силуэтом человека в шапке открывает профиль. Можно изменить имя, часовой пояс и тему: тёмная, светлая, как в системе. Настройки хранятся в аккаунте и применяются после входа с другого устройства. Системная тема отслеживает настройки текущего устройства. Быстрая кнопка темы теперь тоже сохраняет выбор в аккаунте.

Email показывается для информации. Смена email, подтверждение адреса и восстановление забытого пароля через почту — отдельная SD-035 после подключения реального почтового транспорта. В этом патче доступна смена пароля при известном текущем.

Для смены пароля указать текущий пароль, новый (минимум 10 символов) и подтверждение. Текущий браузер остаётся в аккаунте; остальные DB-сессии удаляются, версия авторизации меняется, старые remember-cookie и токены сброса отзываются. Текущие session ID и CSRF обновляются, интерфейс получает новый CSRF автоматически. Пароли не возвращаются API и не сохраняются в браузерном хранилище.

Список устройств показывает браузер, IP и время последней активности. Это активные сессии в пределах срока SESSION_LIFETIME, а не постоянный реестр физических устройств. Обновление списка вручную. Для завершения выбранной чужой сессии требуется текущий пароль. Текущий браузер завершать обычной кнопкой «Выйти».

После отзыва выбранной сессии другие активные сессии сохраняются, но общий токен запомненного входа обновляется: когда другие сессии истекут, может потребоваться повторный ввод пароля. Текущий браузер получает новый токен. Сам таймер задач при выходе/отзыве сессии продолжает работу согласно правилам патча 09.

Управление устройствами использует уже настроенный SESSION_DRIVER=database. Для других драйверов список сообщает о недоступности; смена пароля дополнительно проверяется версией авторизации в сессии. Реальные session ID и содержимое сессий API не возвращает: для выбора используется HMAC-идентификатор. Список и отзыв ограничены владельцем аккаунта. Попытки входа, смены пароля и отзыва сессии ограничены по частоте.

## Проверки

Добавлено 10 backend-тестов, всего 72 WorkspaceTest: профиль и разделение аккаунтов; валидация/гости; неверный текущий пароль; смена пароля с отзывом остальных сессий и обновлением CSRF; подтверждение и запрет прежнего пароля; старая версия авторизации; изоляция списка устройств и сокрытие session ID; выбранный отзыв и проверка пароля; неподдерживаемое хранилище; ограничение попыток входа.

Здесь нет PHP/Docker: серверные проверки запускаются командой установки на Ubuntu. TypeScript/Vite и существующие 8 frontend-тестов проверены при подготовке.

Ручная проверка:
1. Изменить имя и тему, обновить страницу — выбор сохраняется.
2. Включить «Как в системе», сменить тему Ubuntu — сайт следует ей.
3. Войти во втором браузере/приватном окне; оба сеанса появляются в списке после обновления.
4. Завершить второй сеанс из первого, обновить страницу второго — требуется вход.
5. Войти снова во втором браузере; изменить пароль в первом. Первый остаётся в аккаунте, второй после обновления требует вход. Старый пароль больше не подходит.

## Откат

Откат миграции удаляет выбор темы и версию авторизации. Изменённые пароли не восстанавливаются: продолжает действовать последний сохранённый пароль. Удалённые сессии не возвращаются. Код/миграцию откатывать согласованно; не применять rollback вслепую после появления следующих миграций.
