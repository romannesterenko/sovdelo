## Интерфейс

В шапке — колокольчик и счётчик непрочитанных. Центр показывает последние 30 записей, более старые загружаются кнопкой. Можно отметить одну запись или все прочитанными, открыть задачу. Архивную или удалённую задачу сначала восстановить через архив/корзину; история уведомлений сохраняется. Заголовок записи фиксируется на момент доставки.

В «Настройки напоминаний» включаются все напоминания и отдельно дедлайны; выбирается время дедлайна (по умолчанию 09:00). Часовой пояс берётся из настроек аккаунта. Напоминание о дедлайне приходит один раз на дату крайнего срока, а не каждый день просрочки. Изменение даты крайнего срока создаёт новое событие; возврат к уже обработанной дате не отправляет его повторно. Плановая дата задачи сама по себе не является дедлайном.

Для разового напоминания: сохранить задачу, оставить её детали открытыми, нажать колокольчик → «Напомнить о …», выбрать будущие дату и время. Можно заменить или отменить ещё не наступившее напоминание. Это самостоятельное сохранение, не требующее кнопки сохранения деталей задачи. Отменённое напоминание не удаляет уже доставленную историю. Для нового напоминания после доставки требуется другое время.

Разовое время хранится как UTC-момент: смена часового пояса аккаунта меняет отображение, но не момент напоминания. Дедлайны, наоборот, следуют времени и поясу аккаунта. Несуществующее местное время при весеннем переводе часов отклоняется.

Завершённые, архивные и удалённые задачи и задачи архивных проектов исключаются из генерации. Если их восстановить/вернуть в работу, пропущенное напоминание будет обработано, если ещё не было доставлено. Отключение настроек приостанавливает доставку, не удаляя историю и назначенное время; повторное включение обрабатывает пропущенные события.

## Как выполняется доставка

При открытом сайте запрос проверяется раз в 30 секунд, при возврате во вкладку и восстановлении сети. Проверка и создание записей выполняются также при открытии центра. Если сайт закрыт и планировщик не работает, пропущенные записи будут созданы при возвращении. Просроченные задачи с прежними дедлайнами могут дать уведомления при первом запуске.

Для работы в фоне открыть второй терминал:

```bash
cd ~/Projects/sovdelo
php artisan schedule:work
```

Он выполняет генерацию повторяющихся задач и напоминания раз в минуту. Запуск напоминаний вручную: `php artisan sovdelo:reminders`. Расписание использует непосредственную запись в БД, поэтому отдельный worker для этого режима не нужен. Вывод фоновой команды — `storage/logs/reminders.log`.

Поддерживается обработка через стандартную Laravel-очередь:

```bash
php artisan sovdelo:reminders --queue
php artisan queue:work --tries=3 --timeout=60
```

Первый вызов ставит задания для аккаунтов, второй обрабатывает их. Это альтернативный ручной режим; расписание по умолчанию работает напрямую. Ошибки queued jobs используют штатные failed_jobs и `php artisan queue:failed`; ошибки приложения — `storage/logs/laravel.log`. Перезапущенные задания не дублируют записи: используется блокировка пользователя и уникальный ключ события. Серверные процессы и cron настроим при размещении на сервере.

## Проверки

11 новых backend-тестов, всего 62 WorkspaceTest: граница выбранного времени; UTC и локальное время; отмена; пропущенная доставка; фильтрация завершённых/архива/корзины; настройки; прочтение и новые события; изоляция пользователей; несуществующее время; переход даты UTC; страницы истории; повтор queued job и изменение дедлайна.

При подготовке прошли TypeScript/Vite и существующие 8 frontend-тестов. Здесь PHP и Docker недоступны — backend-тесты выполняются командой установки на Ubuntu.

Ручная проверка: открыть сохранённую задачу и назначить напоминание через 2 минуты, дождаться колокольчика, открыть задачу из уведомления, отметить запись прочитанной. Обновить страницу — запись не дублируется, прочтение сохраняется. Проверить отмену второго напоминания.

## Откат

Откат миграции удаляет историю уведомлений, назначенные разовые напоминания и настройки. Сначала сохранить нужные данные. Код и миграцию откатывать согласованно; после следующих миграций не применять rollback вслепую.
