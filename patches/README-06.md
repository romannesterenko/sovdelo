# СовДело — патч 06: файлы, цветные метки и комментарии (SD-034)

Требует 01/02/04/05. Резервные копии (03) не требуются и остаются отложенными до сервера/домена.

```bash
cd ~/Projects/sovdelo
unzip -o ~/Загрузки/sovdelo-patch-06-task-details.zip -d .
php artisan migrate
bash test.sh
npm run build
```

Остановите текущий composer run dev (Ctrl+C) и запустите снова: composer run dev. Изменены PHP-параметры локального сервера для файлов до 10 МБ. Обновите страницу.

В карточке задачи под основными полями появились:
- Метки: создание имени и выбор одного из 6 цветов; нажатие на метку назначает/снимает её. Разрешено несколько меток, до 20 на задачу. Метки общие для задач текущего аккаунта, чужие недоступны.
- Файлы: загрузка, скачивание и удаление. До 10 МБ/файл, 50 файлов/задачу и 250 МБ/аккаунт. Поддержаны PDF, изображения JPG/PNG/WEBP, TXT/CSV, ZIP, DOC/DOCX/XLS/XLSX; сервер проверяет тип. Файлы хранятся на диске local вне public, скачиваются отдельным проверяющим права маршрутом как attachment (не выполняются/не встраиваются в страницу). storage:link для них не нужен.
- Комментарии: добавление, изменение, удаление, имя автора и дата. Текст отображается обычным текстом, не HTML. Пока проект личный: доступ имеет только владелец задачи. Участники и совместные обсуждения позже.
- В списке и на доске: цветные метки, SVG-индикаторы и число файлов/комментариев.

Метки/вложения/комментарии сохраняются отдельными действиями сразу, без общей кнопки «Сохранить изменения». Описание/срок/чек-лист сохраняются как раньше. Несохранённый текст комментария/метки учитывается в предупреждении при уходе. Ошибка запроса не очищает введённый текст. Форма задачи заблокирована на время операций с файлами/комментариями для предотвращения гонок.

Удаление вложения/задачи удаляет связанные записи, файлы очищаются после коммита транзакции. Ошибки физического удаления диска надо контролировать по Laravel-логам; отдельная очистка потерянных файлов пока не реализована. Восстановление удаления появится в этапе корзины. Бэкапы файлов, внешнее хранение и офлайн-кеш по-прежнему отложены.

На production позднее нужно согласовать upload_max_filesize, post_max_size и лимит Nginx. Если используете php artisan serve напрямую без composer dev, запускайте:

```bash
php -d upload_max_filesize=12M -d post_max_size=14M artisan serve --host=127.0.0.1 --port=8010
```

Проверки: TypeScript и Vite-сборка пройдены в среде подготовки. Добавлено 6 Laravel-сценариев (всего 25 в WorkspaceTest): CRUD комментариев/меток, счётчики, приватные файлы, чужой аккаунт, неправильный task_id и ограничения загрузки. PHP/Docker здесь отсутствуют; реальный тестовый проход ожидается на Ubuntu.

Ручная проверка:
1. Создать «Срочно» красного цвета, назначить задаче и обновить страницу.
2. Загрузить небольшой PDF/TXT/PNG, скачать; проверить имя и содержание.
3. Добавить комментарий, изменить его, проверить после обновления.
4. На доске/списке проверить метки и счётчики.
5. Во втором аккаунте проверить отсутствие чужих меток/задач и запрет чужой ссылки скачивания.
6. Отменить удаление, затем подтвердить; проверить счётчики.
