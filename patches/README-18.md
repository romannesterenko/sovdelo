# Патч 18 — стабильный API v1 (SD-016)

После 17. Подготовлен общий API для собственных устройств; роли/MCP/автономный агент отложены SD-038–043. Контракт — docs/api-v1.md.

```bash
cd ~/Projects/sovdelo &&
unzip -o ~/Загрузки/sovdelo-patch-18-api-v1.zip -d . &&
php artisan migrate &&
bash test.sh &&
npm run test:frontend &&
npm run build &&
bash scripts/check-git.sh &&
git add app bootstrap routes database resources tests docs deploy/local/check-api.py patches &&
git commit -m "СовДело: API v1 и токены устройств" &&
git push
```

Actions повторит проверки и выложит после успешного прохождения. Новых GitHub Secrets и root-установщиков не нужно. Миграция создаёт токены/квитанции и версии записей; существующие данные не сбрасываются. Резервная копия перед деплоем используется как в патче 16.

Добавлено: Bearer-вход на 30 дней с read/write, отзыв, единая структура ошибок, пагинация/лимиты; проекты, задачи/чек-листы, порядок, архив/корзина, столбцы и таймер/вся история. Запросы создания защищены Idempotency-Key, изменение задач/проектов — expected_version. Версии увеличиваются также от веб-изменений. Запуск таймера и восстановление используют существующие сервисы под блокировкой аккаунта.

Профиль → «Подключённые приложения» показывает устройства API без токенов и позволяет отозвать их с текущим паролем. При смене пароля старые токены отклоняются по версии авторизации. Веб-логин и его сессии сохранены; API не принимает cookie вместо Bearer.

После зелёного Actions можно проверить сайт локальным интерактивным скриптом:

```bash
cd ~/Projects/sovdelo
python3 deploy/local/check-api.py
```

Ввести email/пароль серверного аккаунта в терминале. Пароль не выводится; временный read-токен хранится только в памяти и отзывается по завершении. Скрипт не меняет проекты/задачи. Пароли/токены в чат не отправлять.

Проверки: 14 новых backend-тестов, всего 103 WorkspaceTest: вход и hash токена; единые ошибки/валидация; read-only; срок/версия пароля; идемпотентность; разделение проектов/задач/устройств; чек-лист/столбец; устаревшая версия после веб-изменения; перенос и версии; архив/корзина/restore; пагинация; общий таймер и история; отзыв из веб-профиля; ограничение входа. Здесь PHP/PostgreSQL недоступны — тесты запускаются локально и в CI. При подготовке прошли Vue/TypeScript build, 14 frontend-тестов и 20 тестов деплоя.

API пока не включает полноценную синхронизацию с курсорами и разрешением конфликтов, агентские аккаунты/проектные роли, MCP, операции файлов/комментариев и напоминаний. Ничего из отложенного этапа не включено. Использовать API-токен владельца как токен будущего агента не следует: его область — все собственные данные этого аккаунта, не отдельный проект.

Откат миграции удалит API-токены, квитанции и версии, но оставит проекты/задачи/историю. Код откатывать согласованно с миграцией, без автоматического отката БД. Перед откатом сохранить актуальную копию.
