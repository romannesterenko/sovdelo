# СовДело: владелец, помощник и план разработки

Патч 30. Доступ помощника ограничен одним проектом. Это служебная идентичность
ProjectAgent со своим именем, токеном, назначениями и журналом, а не второй
человеческий пользователь с копией личных задач. Данные остаются у владельца.
Приглашения других людей/администраторы/наблюдатели остаются SD-028/038.

## Установка и перенос

1. Установить патч, запустить локальную миграцию и тесты, сборку, commit/push.
2. Дождаться успешного GitHub Actions (серверная миграция выполняется деплоем).
3. На сайте открыть Профиль → Проекты и помощники → Перенести план СовДела.
4. Проверить предпросмотр: 47 карточек — 45 из Trello и SD-044/045 из чата.
5. Нажать Перенести. Повторить предпросмотр: новых должно быть 0.

UUID проекта/45 задач сохранены из предыдущего JSON от 13 ноября.
Сопоставление: UUID своего проекта, затем единственное совпадение имени Совдело;
UUID задачи, затем единственное совпадение кода SD-XXX внутри этого проекта.
Архив и корзина участвуют в сопоставлении, не восстанавливаются автоматически.
Совпадение UUID в другом проекте и неоднозначные коды останавливают транзакцию.
Существующие тексты, статусы, сроки, метки, комментарии и файлы не обновляются.
Новые карточки создаются с исходными критериями приёмки и ссылками Trello.
Trello не архивируется и не меняется: это копирование плана в новую систему учёта.

Полный план: resources/plans/sovdelo-development.json. Это специализированный
формат для встроенного переноса, не файл для старого импорта личных данных.
Частично выполненные клиентские/агентские этапы оставлены открытыми. SD-045
проверяет 29/29а: успешное выполнение пользователем пока не подтверждено.

## Ответственность

- Владелец: ставит задачи, выбирает проект и исполнителя, разрешает работу,
  принимает отчёт, возвращает на доработку и отзывает доступ.
- Помощник: читает задачи одного проекта, предлагает новые в бэклог, берёт
  разрешённую задачу в работу, пишет комментарий, отмечает блокировку,
  передаёт результат на проверку с отчётом. Не принимает собственную работу.
- Новый task, созданный помощником, попадает в Бэклог. Владелец переводит его
  К выполнению. Основной порядок: todo → doing → review → done.
  blocked/resume доступны назначенному исполнителю; changes возвращает todo.
- Владелец остаётся владельцем данных и может управлять доской привычным способом.
  При переносе на обычной доске состояние определяется реальным столбцом задачи.

Отдельные столбцы sd-backlog, sd-blocked, sd-review создаются по необходимости;
их семантика сохраняет todo/doing/done для существующих приложений и таймера.
Журнал фиксирует действия нового API/панели и перенос плана. Это не полный аудит
всех старых веб-маршрутов: обычные ручные правки пока в этот журнал не попадают.
Отчёты/комментарии помощника видны также в обычных комментариях с префиксом имени.

## Выдача и отзыв доступа

Профиль → Проекты и помощники → выбрать проект → Доступ помощника.
Имя и текущий пароль владельца обязательны. Токен показывается один раз;
сервер хранит SHA-256, срок 30 дней. Отзыв, смена пароля и истечение срока
прекращают доступ; назначение на задаче остаётся для истории и переназначения.
Токен агента имеет только agent:project и не работает в обычном API устройств,
синхронизации аккаунта, настроек, удаления, файлов или других проектов.
Внутри транзакции записи доступ проверяется повторно после блокировки владельца.
Токены помощников управляются отдельно от обычных подключённых приложений.

Не вставлять токен в чат, Git, команды с аргументом секретного значения или JSON
плана. Локальная настройка спрашивает его скрытым вводом и пишет только в
~/.config/sovdelo/agent.json (0600), вне проекта:

```bash
cd ~/Projects/sovdelo
python3 integrations/mcp/sovdelo_mcp.py --setup
python3 integrations/mcp/sovdelo_mcp.py --check
```

setup проверяет только чтение контекста: задач не создаёт и не двигает.
Существующий файл не перезаписывает. Для нового токена можно передать другой
--config. Файл хранит секрет в открытом виде с правами 0600: это не системный keyring.

## Подключение инструмента

Локальный MCP stdio-сервер запускается Python 3 без сторонних пакетов.
Он не запускает shell/код из задач, не опрашивает очередь в фоне и не вызывает
модель по API. Работу выполняет агент подключённого клиента по указанию человека.
Проверяется протокол 2025-06-18; старые initialize 2024-11-05/2025-03-26 принимаются.

Пример для MCP-клиента, который запускает процессы на компьютере Романа:

```toml
[mcp_servers.sovdelo]
command = "python3"
args = ["/home/roman/Projects/sovdelo/integrations/mcp/sovdelo_mcp.py"]
tool_timeout_sec = 60
```

Для локального Codex можно добавить без ручной правки конфигурации:

```bash
codex mcp add sovdelo -- python3 /home/roman/Projects/sovdelo/integrations/mcp/sovdelo_mcp.py
```

Для удалённых клиентов подготовлен stateless Streamable HTTP endpoint:
https://xn--b1aedylep.xn--p1ai/api/v1/agent/mcp . Требует Authorization: Bearer
(токен выбранного исполнителя). Транспорт tools-only: JSON POST, без SSE, серверных
уведомлений или общей MCP-сессии. Это приватный endpoint, не публичный анонимный сервис.

ВАЖНО: установка Laravel-патча или запуск setup не добавляет инструменты автоматически
в текущий браузерный чат. ChatGPT web использует MCP через подключённый плагин,
а локальная конфигурация относится к локальному desktop/CLI/IDE-клиенту.
Для hosted-чата потребуется отдельно настроить/установить подключение, способное
передавать защищённую авторизацию, и проверить появление инструментов. OAuth и
публикация плагина не входят в патч 30. До этого нельзя утверждать, что помощник
этого чата уже читает или меняет сайт.

Официальная документация подключения:
https://learn.chatgpt.com/docs/extend/mcp?surface=app
Спецификация протокола:
https://modelcontextprotocol.io/specification/2025-06-18/basic/transports

## Инструменты и API

- sovdelo_context: проект, служебная идентичность, ограничения.
- sovdelo_tasks: page/q; до 50 задач, постранично, с workflow и version.
- sovdelo_task: task_id, свежая версия и отчёт.
- sovdelo_create: title, description, request_key (UUID), только бэклог.
- sovdelo_action: task_id, expected_version, action claim/block/resume/submit/comment,
  note для block/comment, report для submit, request_key (UUID).
- sovdelo_activity: before_id для истории, по 100 записей.

REST тот же: GET context/tasks/tasks/{id}/activity;
POST tasks, tasks/{id}/actions. База /api/v1/agent.
Перед записью читать version. Все записи требуют Idempotency-Key UUID.
После обрыва повторять тот же ключ и тело: квитанция возвращает исходный результат,
а не выполняет переход/комментарий повторно. Изменение тела или устаревшая версия — 409.
Ключи квитанций изолированы по исполнителю и не смешиваются с обычным API.
Заголовок токена не пересылается на HTTP redirects. 401/403 не вызывают бесконечный retry.

## Проверка перед учётом реальной работы

1. Выполнить bash test.sh, npm run test:frontend, npm run build.
2. python3 integrations/mcp/test_bridge.py — 7 проверок stdio/транспорта.
3. На сайте перенести план два раза: второй раз 0 новых, старые задачи сохранены.
4. Выдать токен на проект, проверить --setup/--check.
5. Подключённым MCP-клиентом создать тестовую задачу. Владелец разрешает её;
   помощник делает claim → submit с отчётом; владелец принимает или возвращает.
6. Проверить 409 при старой версии, отказ других проектов/обычного API,
   невозможность accept/delete помощником и прекращение доступа после отзыва.

PHP/Docker отсутствуют в среде подготовки: backend-тесты добавлены, но здесь
не запускались. Сборка Vue и проверки Python выполняются при подготовке ZIP.
