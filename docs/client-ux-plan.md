# Приложения СовДело: этап удобства до повседневного использования

Текущий Flutter-клиент — технический прототип. Пользователь подтвердил, что функции
работают, но пользоваться интерфейсом неудобно. Согласован порядок: сначала базовая
функциональность/надёжность синхронизации, затем отдельный этап переработки UX.
Текущий интерфейс не считается согласованным конечным дизайном приложения.

После меток и вложений:

- Убрать стартовый экран проверки SQLite/хранилища/уведомлений из обычного сценария;
  диагностику вынести в настройки. После запуска открывать рабочее пространство.
- Общая навигация: задачи/доски, проекты, поиск, настройки аккаунта и устройств.
- Телефон: компактные карточки, удобный полноэкранный просмотр/редактор задачи,
  клавиатура не перекрывает действия, нормальные зоны нажатия, понятный возврат.
- Linux: список/доска и деталка с полезным использованием ширины, клавиатурные действия.
- Единая деталка с понятными разделами вместо цепочки перегруженных попапов.
- Быстрое добавление, фильтры по проекту/статусу/меткам, понятные пустые состояния.
- Состояние связи/синхронизации без постоянной ручной работы. Очередь не должна
  блокировать всё приложение на время сетевого таймаута; отдельная работа с конфликтами.
- Сохранить согласованный стиль СовДела, цвета и терминологию сайта.

Приёмка UX: создать/найти задачу, изменить срок/проект, отметить пункт, написать
комментарий и приложить файл на телефоне и Linux без технических экранов и инструкций;
повторить основные действия без интернета и проверить понятность состояния отправки.
Упаковку/установщики и окончательную публикацию выполнять после этого этапа.
Роли/агент/API-MCP остаются отдельной более поздней частью плана.
