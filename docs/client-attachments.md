# Этап 27 — вложения Android/Linux

Кнопка «Файлы (N)» в карточке аккаунта открывает список, добавление и «Сохранить как…».
N — серверный счётчик последнего обновления, ожидающие файлы показываются отдельно.
Список кэшируется после первого чтения. Файлы скачиваются по требованию; готовые
локальные копии можно экспортировать без сети. Автооткрытие внешним просмотрщиком,
предпросмотры и удаление серверных вложений из приложения пока не реализованы.

## Лимиты и копирование

Непустой файл до 10 МиБ, до 50 вложений на задачу, 250 МиБ серверного аккаунта.
Форматы как на сайте: pdf,txt,csv,jpg,jpeg,png,webp,zip,doc,docx,xls,xlsx.
Имя очищается от разделителей/управляющих символов и ограничивается 240 символами.
Сервер повторно проверяет MIME/тип и размер, клиентская проверка их не заменяет.

Выбор FilePicker 13.3.3 использует pickFile и readAsByteStream. Приложение копирует
выбранное содержимое в приватный каталог аккаунта, ограничивая поток 10 МиБ,
затем сохраняет SHA-256 и запись очереди. При ошибке копирования/SQLite новая копия
удаляется. Исходный файл не меняется; после копирования он может быть перемещён/удалён
без потери очереди приложения. В Android системный выбор даёт доступ к выбранному файлу,
широкое разрешение на всё хранилище не запрашивается этим кодом.
При выборе облачного источника сами байты должны сначала стать доступны picker;
очередь считается сохранённой только после успешного локального копирования.

Каталог: рядом с SQLite аккаунта, production-account-ID-v1.sqlite3.files.
Общий локальный лимит копий — 250 МиБ, включая очередь/кэш. Неиспользуемую скачанную
копию можно убрать кнопкой: сайт и исходный файл останутся. Невостребованные файлы
после падения/удаления серверной записи очищаются при открытии аккаунта, когда они
старше суток и не упоминаются в SQLite. Неудалённые копии учитываются в локальном лимите.

## API и повтор загрузки

Миграция PostgreSQL: nullable client_uuid и sha256 в task_attachments. Старые веб-
вложения продолжают работать. Новые API-файлы получают UUID операции и SHA-256.

GET /api/v1/tasks/{id}/attachments: список до действующего лимита 50; DTO id,uuid,
name,bytes,sha256 (nullable у прежних файлов),created_at. Приватного path в ответе нет.
GET /api/v1/tasks/{id}/attachments/{file}: защищённое скачивание, read-токен достаточен.
Проверяются владелец задачи и принадлежность вложения именно этой задаче. Заголовки
Content-Type=application/octet-stream, nosniff, private/no-store, X-File-SHA256.
У прежних файлов без сохранённого хэша сумма вычисляется при скачивании.

POST /api/v1/tasks/{id}/attachments: multipart/form-data, поля operation_uuid,name,
sha256,file. Только write-токен. JSON-лимит 128 КиБ для других API остаётся; только
именованный upload-маршрут допускает multipart до 12 МиБ. Nginx 14m и PHP upload12M/
post14M уже предусмотрены серверной установкой. Размер конкретного файла — до10МиБ.

Fingerprint привязан к задаче, имени, фактическим байтам/размеру и SHA-256. Клиентский
хэш сверяется с загруженным файлом. Под строковой блокировкой пользователя проверяются
receipt, владелец и квоты, затем сохраняются blob, TaskAttachment и api_requests.
Автоматических повторов DB-транзакции с побочным файловым I/O нет. При исключении
новый blob удаляется. Повтор UUID с тем же содержимым возвращает исходный 201 до
повторной проверки квот и не записывает второй blob; другое содержимое — 409.
При аварийном завершении PHP между записью blob и DB commit может остаться серверный
сиротский blob: SQL/filesystem не составляют распределённую атомарную транзакцию.
Это не создаёт вторую видимую запись и не удаляет пользовательские данные; отдельную
очистку таких серверных сирот пока не добавляли.

## Очередь и целостность

SQLite v6 добавляет account_attachments. UUID, имя, байты, хэш и приватный путь копии
сохраняются; task_id фиксируется перед первой HTTP-попыткой, после create задачи.
Перед каждой отправкой повторно проверяются размер и SHA-256 локальной копии.
Нельзя молча отправить изменившиеся байты под прежним UUID. Передача идёт потоком
с Bearer по фиксированному HTTPS origin, без redirect и обхода сертификата, таймаут120с.
Успех помечает запись sent; потеря ответа/сети сохраняет очередь и ту же копию.
404/409/413/422 или повреждённая локальная копия блокируют файл; доступны повтор и
явное удаление блокированной копии с устройства. Автосоздания нового UUID при ошибке нет.

Комментарий/редактирование задачи не конфликтуют с добавлением файла по версии:
вложение не перезаписывает поля задачи. Принятие версии сайта сохраняет его очередь.
Задача с ожидающим файлом остаётся видимой даже после архива/удаления на сайте.
Полное подтверждённое удаление локальных изменений недоступной задачи очищает и
её ожидающие записи вложений; blob станет сиротским и уберётся локальной очисткой.

Скачивание пишет .part, ограничивает поток и проверяет SHA-256 заголовка. Перед
атомарным переименованием дополнительно сравниваются размер/ожидаемый известный хэш;
ошибка не подменяет прежнюю копию. «Сохранить как…» передаёт проверенные байты в
системный диалог. Автоматического экспорта файлов наружу нет. Список отражает удаления
на сайте после обновления, неподтверждённые файлы при этом сохраняются.
Токен не записывается рядом с blob/в таблицу. Копии разных аккаунтов разделены.

## Окружение и проверка

Добавлены file_picker 13.3.3 и crypto. flutter pub get обновит pubspec.lock: сохранить
его вместе с изменениями клиента. Linux picker использует GTK3/XDG Desktop Portal,
они присутствуют в обычном GNOME. Источники выбранного API:
https://pub.dev/documentation/file_picker/latest/
https://pub.dev/packages/file_picker_linux
https://pub.dev/packages/crypto

1. Остановить приложение, установить патч, запустить PostgreSQL и php artisan migrate.
2. Laravel-тесты и Flutter analyze/test, затем commit/push, дождаться зелёного Actions
   с production-миграцией. Полностью перезапустить Flutter: добавлен нативный plugin.
3. Linux/Android: добавить небольшой txt/pdf/картинку. Проверить сайт и скачанные байты.
4. Отключить сеть, выбрать файл, дождаться сохранения локальной копии и ошибки сети.
   Переместить исходник, перезапустить приложение. Включить сеть, синхронизировать:
   вложение одно, содержимое прежнее. Повторить с ещё не отправленной задачей.
5. Скачать файл с сайта, отключить сеть, «Сохранить как…» из кэша. Проверить исходные байты.
6. Проверить неподдерживаемый формат, >10МиБ, блокировку при 50 файлах и readonly-токен.
7. Удалить вложение на сайте и обновить список; остальные кэш/очередь должны сохраниться.

Добавлены 4 Laravel- и 8 Flutter-проверок: повтор/квота, приватность/скачивание,
валидация/права/JSON-limit, собственная копия, рестарт, потеря ответа, сбои/размер,
повреждение, кэш/SHA, ожидание create и миграция v5. SDK PHP/Flutter здесь отсутствуют,
поэтому тесты запускаются локально. Native picker, реальный multipart/TLS и Android
системное сохранение требуют приёмки на устройствах; unit-тесты их не заменяют.
Установщик, новая SQLite DDL и состав ZIP проверяются отдельно.
