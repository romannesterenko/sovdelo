# Этап 24 — офлайн-чек-листы в приложении

В редакторе задачи аккаунта: добавление, переименование, удаление пунктов, отметка
выполнения, счётчик; на карточке — локальный прогресс N/M и полоса выполнения.
Изменения вступают в силу только после «Сохранить». «Отмена» не меняет SQLite/очередь.
Текст пункта — 1–500 символов после trim, до 100 пунктов. Пустой пункт нужно заполнить
или удалить. Полностью пустой список допустим и отправляется как [].
Завершение всех пунктов не меняет семантический статус задачи автоматически.

SQLite аккаунта обновляется v2 → v3 в прежнем файле. Добавлена checklist_json,
первоначальное значение берётся из сохранённой серверной копии. Новые базы сразу v3;
прямое обновление v1 → v3 также поддерживается. Подготовленные UUID/тела очереди,
локальные поля и статусы сохраняются. Старые числовые boolean из API/кэша приводятся
к bool на входе; локальный редактор и исходящие операции используют настоящий bool.
Не удалять базу и не переустанавливать приложение с очисткой данных.

POST /api/v1/sync/operations, kind=edit дополнен fields.checklist:
```json
{"operation_uuid":"UUID","kind":"edit","task_id":123,"expected_version":2,
 "fields":{"checklist":[{"text":"Проверить","done":true}]}}
```
Передаётся полный список с сохранением порядка. Изменяется только это поле, если
других ключей нет. Сервер запрещает неизвестные ключи пункта, неправильную длину,
не-списки и отсутствие text/done. Порядок ключей text/done не влияет на fingerprint;
порядок пунктов имеет значение. Успешный повтор возвращает исходное подтверждение.
Ограничение HTTP тела API остаётся 128 КиБ. Клиент отклоняет правку более 120 КиБ
JSON изменённых полей до записи в SQLite, оставляя запас для UUID и версии.
При очень больших текстах нужно сокращать список или сохранять описание отдельно.

Чек-лист — часть общей версии задачи. Pull не заменяет локальный список при наличии
очереди; последующие правки сохраняются даже при подтверждении более ранней операции.
При 409 сохраняется локальный список и показываются обе версии в диалоге конфликта.
«Принять сайт» после подтверждения заменяет также чек-лист. Автослияния пунктов нет.
Офлайн-правка ещё не созданной на сервере задачи уходит после подтверждения create.
Фоновая синхронизация и drag-and-drop пунктов в этот патч не входят.

## Проверка

1. Тесты, commit/push, дождаться зелёного Actions. Затем обновить Linux/Android.
2. Открыть задачу аккаунта → «Редактировать». Добавить несколько пунктов, отметить
   один, изменить текст другого, удалить третий, сохранить. Проверить сайт и прогресс.
3. Изменить список и нажать «Отмена»: исходное состояние должно остаться.
4. Без интернета изменить чек-лист, закрыть/открыть приложение: пункты и очередь
   сохраняются. Включить сеть и нажать «Синхронизировать».
5. Удалить все пункты, сохранить: на сайте должен остаться пустой список.
6. Изменить тот же список на сайте при неподтверждённой локальной правке:
   синхронизация должна остановить задачу на конфликте, не затереть сайт.
7. Повторить для задачи, созданной офлайн до её первой отправки.

Добавлены 3 Laravel-проверки (повтор/очистка, валидация/атомарность, конфликт) и
7 Flutter-проверок сохранения/повтора, очистки, pull/конфликта, отката, legacy-bool,
размера UTF-8 и миграции v2. Существующие тесты миграции v1 также остаются.
В среде подготовки нет PHP/Flutter, поэтому эти тесты запускаются локально.
Установщик проверяется отдельно: соответствие патчу 23, копия исходников,
повторное применение, защита ручных правок. PostgreSQL-миграция не нужна.
