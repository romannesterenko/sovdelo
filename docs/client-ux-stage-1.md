# Этап 28 — первый этап удобства Android/Linux

Стартовый экран теперь рабочее пространство аккаунта. Прежние тестовые задачи,
проверка SQLite/метки хранилища/уведомления сохранены в «Настройки → Диагностика».
Тестовая база не импортируется и не удаляется. Авторизация, ключ хранилища и каталог
базы аккаунта остаются прежними. Миграций PostgreSQL/SQLite и новых пакетов нет.

## Навигация и список

На узком экране нижняя навигация «Задачи / Проекты / Настройки»; при ширине >=1000
боковая панель. В проектах показано число локально известных задач; нажатие открывает
список с фильтром. Настройки содержат аккаунт, состояние очереди, метки, диагностику,
выход. Метки больше не занимают постоянную панель действий над списком.

Компактная карточка открывается целиком нажатием; отдельная круглая кнопка завершает
задачу/возвращает в todo. Видны название (до двух строк), статус, проект, срок,
приоритет, чек-лист, счётчики комментариев/файлов, до трёх меток и индикатор очереди.
Конфликт показан значком, разбирается в деталке. Прежняя россыпь кнопок убрана.

Поиск по локальным названию/описанию без учёта регистра; фильтры статуса, проекта,
метки и ожидающих изменений сочетаются. «Без проекта» отделён от «Все проекты».
Фильтр очереди учитывает комментарии и файлы. Фильтры не меняют базу и не отправляют
запросы. Список строится лениво. Заголовок с фильтрами прокручивается вместе с ним,
чтобы клавиатура поиска не создавала фиксированный переполненный столбец.
Фильтры в этом этапе не сохраняются между перезапусками.

Плавающий «+» открывает быстрое добавление с выбором проекта. Выбранный в списке
проект подставляется по умолчанию. AccountStore.add теперь возвращает local_id и
принимает необязательный projectId; задача, create и последующий edit(project_id)
пишутся одной SQLite-транзакцией. Используется прежний протокол API, без нового
маршрута создания. После добавления фильтры сбрасываются до выбранного проекта,
чтобы новая задача не пропала из-за старого поиска/статуса/метки.

## Деталка

При ширине <720 отдельный экран, на широком — окно до 1000px и 90% высоты.
Деталка показывает локальные поля, вкладки описания/чек-листа, статус, метки, проект,
срок, очередь и входы в комментарии/файлы. Пункты можно отмечать прямо здесь.
Отметка/статус отображаются оптимистично; после действия перечитывается фактическая
SQLite-запись, поэтому сбой записи не остаётся визуальным «успехом».

Редактор, комментарии и файлы на телефоне открываются полноценными экранами с
прокруткой и возвратом, на широком экране используют прежние диалоги. Кнопка сохранения
редактора находится в верхней панели телефона. На Linux комментарии/файлы пока могут
открываться вторым диалогом поверх деталки; объединение всех редакторов в одну панель
остаётся следующей частью UX. Никакой файл/комментарий не исчезает при смене вкладки.
Технические версии и UUID не показываются в обычной карточке.

## Что ещё не исправлено

Это первый этап UX, не завершение всего docs/client-ux-plan.md. Сеть/очередь пока
исполняются прежним способом: во время запроса запись и открытие другой задачи могут
ждать сетевого таймаута; поиск/фильтры и чтение списка доступны. При запуске сохранённый
список показывается до завершения обновления, но действия пока блокируются busy.
Следующий шаг — раздельные состояния UI/синхронизации и сериализованный worker,
чтобы не блокировать интерфейс на таймаутах. Затем доска, фильтры/действия клавиатуры
и объединение разделов в одной деталке. Фоновую синхронизацию этим патчем не объявляем.

## Проверка

1. Установить, flutter analyze/test, полностью перезапустить (q → flutter run).
2. Сохранённая сессия должна открыть рабочий список без тестового экрана.
3. Проверить телефон и широкое окно Linux, длинные названия/метки, клавиатуру поиска.
4. Найти задачу по описанию, совместить статус/проект/метку, сбросить фильтры.
5. В проектах открыть проект, создать задачу через «+», проверить её назначение.
6. Открыть деталку, отметить пункт, сменить статус, отредактировать описание/срок,
   добавить комментарий и файл. Проверить сохранение на сайте и офлайн-очередь.
7. В настройках открыть диагностику: прежние тестовые задачи должны сохраниться.
8. Проверить выход/вход и чтение с read-токеном, конфликты и сохранность ожидающих файлов.

Добавлены проверки фильтров/дат, карточки на 320/1280px, открытия карточки и чек-листа
деталки, атомарного быстрого добавления проекта. Flutter SDK здесь отсутствует;
widget/model тесты подготовлены, но не запускались. Скриншоты фактического Flutter UI
не проверялись. Установщик проверяется отдельно. Серверный деплой для интерфейса не
требуется; обычный push всё равно запускает существующие проверки GitHub Actions.
