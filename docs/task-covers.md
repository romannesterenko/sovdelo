# Обложки задач на сайте — патч 32

Приоритет: веб-доска. Разработка Android, Linux и OAuth остаётся на паузе.

При загрузке первого растрового изображения оно автоматически становится обложкой,
если обложка ещё не выбрана и пользователь ранее не отключил её. Следующая загрузка
сохраняет выбранную обложку. Другой файл выбирается кнопкой «Сделать обложкой» во
вкладке «Файлы». Кнопка «Обложка и файлы» в карточке открывает эту вкладку.

Обложка показана над заголовком на доске и в верхней части открытой карточки.
Изображение вписывается целиком: скриншоты не обрезаются. У изображений во вложениях
есть превью. Скачивание самого вложения сохраняется.

«Убрать обложку» очищает только её выбор. Файл остаётся. Последующие загрузки не
включают обложку обратно автоматически: её можно явно выбрать из вложений.
Удаление выбранного вложения тоже снимает обложку, без подстановки другого файла.
Обычные поля открытой карточки при смене обложки не перезаписываются.

## Данные и безопасность

Миграция 2026_11_20_000018 добавляет mime_type/image_width/image_height вложениям,
cover_attachment_id (FK с nullOnDelete) и cover_disabled задачам. Личные файлы
остаются в закрытом storage. Изображение определяется по содержимому getimagesize,
а не по имени или MIME из браузера. Поддерживаются JPEG/PNG/WebP/GIF, SVG не служит
обложкой. Общий лимит файла — прежние 10 МБ; отдельный публичный каталог не создаётся.

GET /tasks/{task}/attachments/{attachment}/preview проверяет владельца задачи и
принадлежность вложения; отдаёт разрешённый image MIME inline, nosniff, private/no-store
и ограничивающий CSP. Обычное скачивание остаётся application/octet-stream.
Превью использует браузерную авторизацию сайта, не публичный URL с секретом.

PUT /tasks/{task}/cover: attachment_id (nullable), expected_version. Чужой файл,
неизображение и устаревшая версия не могут изменить обложку. Выбор и загрузка
сериализуются той же блокировкой владельца, что другие действия задачи.
Обложка входит в общую версию задачи, чтобы изменения увидели другие устройства.

Существующие вложения получают метаданные при открытии списка файлов/превью;
их можно назначить вручную. Старая задача не получает обложку просто от миграции.
При загрузке через существующий API применяется то же правило первой обложки.
Повтор идемпотентного upload не выбирает обложку заново после её снятия.
Клиентские приложения в патче не изменяются.

Оригиналы изображений используются с lazy loading; серверные миниатюры пока не
генерируются. Экспорт JSON по-прежнему не переносит содержимое вложений и выбор
обложки; резервные копии PostgreSQL + storage сохраняют их вместе с остальными данными.

## Проверка

TaskCoverWorkspaceTest: 11 backend-сценариев (автовыбор, сохранение выбранного,
снятие без удаления, ручная замена, не-изображение, старые вложения, приватное превью,
чужие вложения/задачи, удаление, версия, API retry и гость). Имя содержит WorkspaceTest,
поэтому прежний фильтр тестов в test.sh/CI включает новый класс.

В среде подготовки выполнены сборка TypeScript/Vue и 14 frontend-тестов. PHP и
PostgreSQL отсутствуют, backend-сценарии здесь не запускались. Попытка браузерной
проверки остановилась ограничениями среды (Chromium socket Operation not permitted).

Ручная приёмка после деплоя:
1. Загрузить PNG/JPEG → обложка появляется на доске и в карточке.
2. Загрузить вторую картинку → первая остаётся; выбрать вторую вручную.
3. Снять обложку → оба файла остаются; обновить страницу → обложки нет.
4. Добавить ещё изображение после снятия → выбор не включается сам.
5. Назначить существующее изображение и удалить его → обложка снимается.
6. Изменить название, не сохранять; выбрать/снять обложку во вкладке «Файлы» →
   введённое название сохраняется в редакторе.
