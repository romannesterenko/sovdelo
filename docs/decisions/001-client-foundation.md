# ADR-001: общая основа приложений СовДело

Дата: 2026-11-13. Статус: кандидат, ждёт проверки Ubuntu + Android (SD-017).

## Решение

Проверяем Flutter для Android, Linux и будущего Windows. Laravel остаётся сервером,
Vue — веб-интерфейсом. Мобильный и настольный клиенты используют существующий API v1.
Цвета, смысл статусов, терминология и сценарии общие; компоненты Vue во Flutter не переносятся.

| Критерий | Flutter | Tauri + Vue |
| --- | --- | --- |
| Существующий веб-код | UI пишется на Dart | Можно повторно использовать Vue |
| Android, Linux, Windows | Официальные целевые платформы | Целевые платформы Tauri 2 |
| Локальная БД | SQLite: sqflite Android, FFI desktop | SQL plugin SQLite |
| Защищённый токен | Flutter Secure Storage, проверка системного хранилища | Нужен выбор и проверка отдельного хранилища |
| UI телефона | Общая система виджетов, адаптивная компоновка | Требует адаптации текущего веб-интерфейса |
| Цена выбора | Новые Dart/Flutter и UI | Rust/native toolchain и интеграция плагинов |

Flutter выбран кандидатом из-за приоритета Android и общей логики приложения.
Tauri остаётся альтернативой, если реальные сборки или системные интеграции окажутся неудобны.
Окончательное решение принимаем после воспроизводимого запуска на устройствах,
а не по наличию названия платформы в документации.

## Ограничения проверки

Прототип проверяет SQLite после перезапуска, запись/чтение/удаление тестовой метки
в защищённом хранилище и немедленное локальное уведомление.
Он не проверяет push, работу при закрытом приложении, напоминания по расписанию,
синхронизацию, релизную подпись и Windows. Это отдельные задачи.
Android minSdk23 выбран по требованиям защищённого хранилища; при необходимости
поддержки более старых телефонов решение пересматриваем до основного клиента.
Прототип использует отдельную БД и тестовую метку без входа в боевой аккаунт.

## Следующая архитектура (ещё не реализована)

Локальная SQLite — источник данных интерфейса. Изменения записываются транзакционно
в локальные данные и очередь исходящих операций. Отправка использует UUID/идемпотентность,
версии объектов и явные конфликты API. Нужен отдельный договор синхронизации,
включая удаления, курсоры и восстановление после потери сети: CRUD API v1 его не заменяет.
Токен — только в системном защищённом хранилище. Напоминания проектируются отдельно
для возможностей ОС. Учётные записи и роли агентов остаются задачами будущего этапа.
