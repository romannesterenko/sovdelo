# Этап 20: локальные задачи и журнал исходящих изменений

Статус: реализована локальная основа, ожидает проверки Flutter на устройствах.
Реальная отправка на API и вход ещё не реализованы.

## Контракт локальной записи

SQLite schema v2: tasks получают постоянный UUID v4 и local_revision.
Изменение задачи и снимок операции в outbox записываются одной транзакцией.
Каждая операция имеет собственный постоянный UUID, номер локальной версии,
порядок sequence, время UTC и JSON-снимок title/status. Предыдущие снимки не меняются.
Одинаковое состояние повторно не записывается. Чтение очереди её не очищает.

Миграция с прототипа v1 сохраняет ID, названия и done. Каждой существующей задаче
выдаётся UUID и операция create с текущим состоянием. Повторное открытие не повторяет
миграцию. При ошибке SQLite откатывает миграцию целиком.
База остаётся probe.sqlite3 в прежнем каталоге приложения. Переустанавливать приложение
с очисткой данных, удалять SQLite или применять flutter clean ради миграции не нужно.
После перехода на v2 запуск старого клиента не поддерживается: не откатывать исходники
поверх обновлённой базы без отдельной процедуры восстановления.

## Граница синхронизации

Outbox пока представляет локальный журнал намерений, не готовые HTTP-запросы.
Текущие записи принадлежат локальному прототипу и НЕ привязаны к аккаунту.
При первом входе будущий клиент должен явно предложить импорт локальных задач
в выбранный аккаунт. Нельзя автоматически отправлять их в любой введённый аккаунт.

Перед подключением отправки нужно реализовать:

- отдельную область данных/очереди на аккаунт и сервер;
- привязку локального UUID к серверному id/uuid/version;
- неизменяемое тело попытки HTTP + постоянный Idempotency-Key для повторов;
- атомарное применение ответа и подтверждение операции только после успеха;
- сохранение очереди при таймауте, 401, 429, 5xx и после перезапуска;
- 409 как явный конфликт, без автоматической перезаписи;
- получение серверных изменений и удалений без потери локальных операций;
- тест потери ответа после успешной записи на сервере.

local_revision не равен серверному expected_version. UUID операции сам по себе
не решает потерю ответа PATCH. Последующая реализация протокола может потребовать
дополнить Laravel API: сегодня безопасные повторы гарантированы только для создания.
Порядок/столбцы, проекты, комментарии, файлы, таймеры и удаления добавляются отдельно.

## Проверки

Автотесты Flutter проверяют перезапуск, миграцию v1, стабильность UUID/снимков,
повтор статуса, откат транзакции при принудительном сбое outbox и пустые названия.
В этой среде Flutter SDK отсутствует; эти тесты подготовлены, но здесь не запускались.

На Ubuntu и Android без интернета: создать задачу, переключить статус, запомнить
счётчик очереди, полностью закрыть/открыть приложение. Задача, статус и счётчик
должны сохраниться. Повтор открытия без правок не увеличивает очередь.
Старые тестовые задачи сохраняются; при первом обновлении каждая добавляет одну
операцию в очередь. Количество операций может быть больше количества задач.
На сайте новые локальные задачи пока не появляются — отправка ещё не подключена.
