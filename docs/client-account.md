# Этап 21 — аккаунт и чтение данных сайта

Отдельный экран «Открыть аккаунт СовДела» в приложении Android/Linux.
Использует существующий production API v1 по фиксированному HTTPS-адресу.
Laravel и API в этом патче не меняются.

## Поведение

Вход: email, пароль, имя устройства и access=read. Пароль очищается из поля после
отправки, на диск не записывается. Токен проверяется через /me и сохраняется только
в Flutter Secure Storage. Ключ отделён от тестовой метки. Следующее открытие экрана
восстанавливает токен и заново проверяет профиль. Срок токена задаёт сервер (30 дней).
Если запись/проверка хранилища не удалась, клиент пытается отозвать новый токен.
Если сервер при этом недоступен, устройство можно отозвать в профиле сайта.

Экран показывает активные задачи и проекты, по 50 на странице, с кнопками навигации.
Смена состояния на сайте отображается после «Обновить». Открытие задачи показывает
название, описание, статус, версию, срок, чек-лист и счётчики комментариев/файлов.
Редактирование, файлы и тексты комментариев пока не подключены.

401 очищает текущую сессию на экране и удаляет сохранённый токен. При сетевой ошибке
токен сохраняется, можно повторить «Обновить». Выход отзывает текущий токен; если
сервер недоступен, удаляет локальный токен и явно сообщает, что отзыв не подтверждён.
Другие устройства не отзываются. Локальная SQLite и исходящая очередь не очищаются.
Данные с сайта находятся только в памяти экрана, offline-cache ещё не реализован.

## Граница этого этапа

Локальная очередь не привязана к аккаунту и не отправляется. Вход не импортирует
тестовые задачи. В API нет запросов на создание/изменение задач в этом клиенте.
Следующий этап должен добавить область SQLite на аккаунт и безопасный протокол
синхронизации. Read-токен тогда заменим write-токеном с отзывом прежнего.

Не логируются пароль, токен и тела ответов. HTTP redirect не выполняется, таймаут
всего запроса 25 секунд, максимальный ответ 2 МиБ. Ошибки сети/авторизации показываются
в интерфейсе. Сертификаты TLS проверяются стандартным HttpClient без обходов.
Android пока запускается в debug-режиме, как и в патчах 19–20; релизная упаковка
и её Android permissions остаются отдельной задачей.

## Приёмка Ubuntu + Android

1. Создать задачу в локальном списке и запомнить очередь.
2. Открыть аккаунт, войти email/паролем сайта; пароль вводится только в приложении.
3. Проверить проекты и задачи. Открыть деталку. При >50 записях проверить страницы.
4. Изменить задачу на сайте и нажать «Обновить» в приложении.
5. Полностью закрыть и открыть приложение, снова открыть аккаунт: повторный пароль не нужен.
6. Отключить сеть: экран аккаунта сообщает ошибку; назад доступны локальные задачи.
7. Восстановить сеть, нажать «Обновить».
8. Отозвать этот токен в профиле сайта: следующий запрос должен предложить вход.
9. Проверить выход: повторное открытие экрана предлагает вход. Локальная очередь прежняя.

При неверном пароле возможен HTTP 422; после нескольких попыток действует rate limit.
Не повторять вход циклом: максимум 20 активных токенов на аккаунт.
Для теста повторного входа сначала выходить, чтобы отозвать старый токен.

Подготовлены 7 unit-тестов контракта входа/сессии/страниц с подменой транспорта.
Они не заменяют проверку TLS/реальной сети, системного Keyring и телефона.
В среде подготовки нет Flutter SDK; анализ, тесты и сборка выполняются локально.
