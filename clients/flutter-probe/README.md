# СовДело — проверка клиентской основы (SD-017)

Это отдельный прототип, не подключённый к аккаунту и боевым задачам.
Основной Laravel/Vue сайт продолжает работать как раньше.

## Ubuntu: окружение

Нужны Flutter stable >=3.44 / Dart >=3.12, Git, Python3 и библиотеки Linux.
Если SDK уже установлен, не устанавливай вторую копию: выполни `flutter doctor -v`.
Если его нет:

```bash
sudo apt update &&
sudo apt install -y git curl unzip xz-utils zip clang cmake ninja-build pkg-config libgtk-3-dev libstdc++-12-dev libsecret-1-dev gnome-keyring &&
mkdir -p ~/development &&
git clone --branch stable https://github.com/flutter/flutter.git ~/development/flutter
```

Добавь SDK в PATH текущего терминала:

```bash
export PATH="$HOME/development/flutter/bin:$PATH"
flutter doctor -v
```

Для следующих терминалов добавь такую же строку `export PATH=...` в `~/.bashrc` один раз.
При работе в GNOME используется системное хранилище секретов. Если оно заблокировано,
разблокируй его в сеансе пользователя. Ошибку нельзя обходить сохранением токена в файл.
Сборка и запуск выполняются от обычного пользователя, без sudo.

## Подготовка и запуск

Из корня репозитория:

```bash
bash clients/flutter-probe/bootstrap.sh &&
cd clients/flutter-probe/app &&
flutter run -d linux
```

Bootstrap создаёт нативные каталоги официальным Flutter SDK, добавляет наш исходный код,
настройки Android, разрешает зависимости, запускает анализ и тест SQLite.
При повторном запуске не перезаписывает app/. Если установка зависимостей прервалась,
запусти bootstrap ещё раз. При неподдерживаемом шаблоне Android приложение не публикуется
в app/; сохрани вывод ошибки. Каталог .scaffold.* временный.
`app/flutter-sdk.json` фиксирует использованный SDK; `app/pubspec.lock` нужно добавить в Git.
Уведомления зафиксированы на 19.5.0: проверяем известный API и Android compileSdk >=35,
не смешивая эту проверку с переходом на 23.x / AGP9. Остальные зависимости фиксирует lock.
Обновлять версии будем отдельным изменением после успешной сборки.

## Приёмка Linux

1. Отключи интернет, добавь задачу, отметь её выполненной.
2. Закрой приложение полностью, открой заново: задача и отметка должны сохраниться.
3. Нажми «Записать защищённую метку». Перезапусти и нажми «Прочитать».
4. Нажми «Показать уведомление». Проверь уведомление в GNOME (также центр уведомлений).
5. Удали защищённую метку, проверь, что при чтении она отсутствует.
6. Проверь узкое и широкое окно, длинное название и список из нескольких задач.

Кнопка уведомления подтверждает только отправку запроса; успешная приёмка требует
видимого уведомления. SQLite и Keyring проверяются независимо.

## Android — второй этап этой же проверки

Установи Android Studio и SDK по официальной инструкции:
https://docs.flutter.dev/platform-integration/android/setup
Нужны JDK17 или совместимая JDK из Android Studio, Android SDK platform не ниже 35
(точную версию запрашивает установленный Flutter), SDK command-line tools, принятые лицензии:

```bash
flutter doctor --android-licenses
flutter doctor -v
flutter devices
```

Подключи телефон с USB debugging или запусти эмулятор. В app/:

```bash
flutter build apk --debug
flutter run -d ID_ИЗ_FLUTTER_DEVICES
```

Повтори приёмку Linux на телефоне, разреши уведомления при запросе.
APK: `app/build/app/outputs/flutter-apk/app-debug.apk`.
Это debug-прототип; публикация, подпись релиза и обновление ещё не реализованы.
Windows-каталог создан для будущей проверки; сборка Windows выполняется на Windows,
сейчас она не проверена. Linux собирается на Linux.

## Git после проверки

Из корня репозитория сохрани и шаблон, и полученное приложение:

```bash
bash scripts/check-git.sh &&
git add clients/flutter-probe docs/decisions patches/README-19.md &&
git commit -m "СовДело: прототип Flutter для проверки клиентской основы" &&
git push
```

Не добавляй build/, .dart_tool/, local.properties, ключи подписи или реальные токены.
Официальный Flutter scaffold содержит правила исключения для этих файлов.
Серверный деплой остаётся обычным; выполнять на сервере flutter не требуется.
